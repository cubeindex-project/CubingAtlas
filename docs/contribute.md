# Contribute to CubingAtlas

CubingAtlas stays useful because cubers share the resources they use. You can help by suggesting a site, correcting outdated information, reporting a broken link, or improving the directory itself. Every contribution is welcome.

## Before you add a resource

Please check whether the resource is already listed and choose the page that best matches its main purpose. A good submission includes:

- the resource's official URL;
- its name and a short, factual description;
- the most appropriate category or section;
- relevant links such as GitHub, documentation, app stores, or a community server; and
- any important context, such as a required platform, language, or paid access.

Prefer official and stable links whenever possible. Please do not submit duplicates, broken links, unrelated sites, or promotional links without a useful cubing resource behind them.

## Quick ways to help

### Suggest a resource or improvement

[Open an issue](https://github.com/cubeindex-project/CubingAtlas/issues/new) with the resource URL, a short description, and the page where you think it belongs. You can also use an issue to suggest a new category or a broader improvement to the atlas.

### Report a broken or outdated link

Use the [broken-link report](https://github.com/cubeindex-project/CubingAtlas/issues/new?template=broken_link.md). Include the page and section containing the link, the broken URL, and an updated URL if you know one.

### Edit a page directly

Each directory page has an **Edit this page on GitHub** link. For small corrections or a single new listing, editing that file in GitHub and opening a pull request is often the quickest option.

## Contributing with a pull request

1. Fork the [CubingAtlas repository](https://github.com/cubeindex-project/CubingAtlas) and create a branch for your change.
2. Edit the relevant Markdown file in `docs/`.
3. Keep listings consistent with the surrounding entries. Use a direct link, a concise description, and optional supporting links separated by `/`.
4. If you are working locally, install dependencies and check the site with:

```sh
npm install
npm run docs:build
```

5. Open a pull request that explains what you added, changed, or removed.

Pull requests are checked for broken Markdown links automatically. Keep changes focused and avoid unrelated formatting changes so they are easy to review.

## Keep the atlas accurate

The best contributions are specific and verifiable. If a project has shut down, is no longer maintained, or has moved to a new URL, let us know. Historical projects may still belong in [Dead Projects](/dead) when they are useful references for the cubing community.

Thank you for helping make cubing resources easier to find.
